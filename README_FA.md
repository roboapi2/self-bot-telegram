# راهنمای فارسی مدیریت و استقرار UserBot Control Center

این پروژه، پنل موجود PHP برای مدیریت چند حساب تلگرام بر پایه MadelineProto است. فایل‌ها قبلاً در همین پوشه قرار دارند؛ نصب از همین سورس انجام می‌شود. پنل فارسی، تم روشن و تیره، ورود QR و دو مرحله‌ای، آرشیو، بازیابی حذف و ویرایش، ساعت پروفایل، کمپین و دستورهای Saved Messages حفظ شده‌اند.

مسیر جدید استقرار Docker و انتشار خودکار: [نصب Docker](docs/DOCKER_INSTALL_FA.md)، [Secrets و CI/CD](docs/CICD_FA.md)، [چک‌لیست تولید و فرمان‌ها](docs/PRODUCTION_DEPLOY_FA.md)، [rollback](docs/ROLLBACK_FA.md)، [ممیزی و محدودیت آزمون‌ها](docs/DOCKER_AUDIT_FA.md). راهنمای زیر مربوط به نصب مستقیم PHP/systemd است؛ هر حساب فقط در یکی از این دو نصب فعال باشد.

راهنمای تکمیل مرحله دوم: [نصب و اعتبارسنجی](docs/INSTALL_FA.md)، [عملیات و چک‌لیست حساب](docs/OPERATIONS_FA.md)، [گزارش نهایی](docs/FINAL_AUDIT_FA.md). اسکریپت بررسی واقعی VPS: `sudo bash scripts/validate-vps.sh`.

## ۱. پیش‌نیاز و محل پروژه

مسیر پیشنهادی سرور `/opt/self` است. اگر پروژه از قبل زیر `/opt`، `/srv` یا `/var/www` قرار دارد، همان مسیر را استفاده کنید؛ نام مسیر نباید فاصله داشته باشد. از `/root` برای سرویس وب استفاده نکنید. سیستم هدف Ubuntu 24.04 LTS با PHP 8.3 با معماری ۶۴ بیتی، PHP حداقل 8.2، SSH و دسترسی sudo است. نیاز حافظه به تعداد حساب‌ها و حجم رسانه بستگی دارد؛ مصرف را با `free -h` بررسی کنید.

برای انتقال همین پوشه از Windows، در PowerShell سیستم خود اجرا کنید؛ `USER` و `SERVER_IP` را جایگزین کنید:

```powershell
scp -r F:\project\self USER@SERVER_IP:/tmp/self-upload
```

سپس در SSH، تنها اگر هنوز `/opt/self` وجود ندارد:

```bash
sudo mv /tmp/self-upload /opt/self
cd /opt/self
```

اگر نسخه‌ای از پروژه روی VPS دارید، پوشه‌ی فعال و داده‌هایش را جایگزین نکنید؛ از روش به‌روزرسانی بخش ۸ استفاده کنید. هیچ‌یک از فرمان‌ها نیازمند یافتن یا بازکردن آرشیو سورس نیست.

## ۲. نصب در همان پوشه

```bash
cd /opt/self
sudo bash scripts/install-vps.sh
```

این فرمان بسته‌های لازم، Composer، Nginx و PHP-FPM را نصب می‌کند؛ وابستگی‌ها را دقیقاً از `composer.lock` می‌گیرد و آزمون‌ها را اجرا می‌کند. حساب سیستم `ubcc` بدون دسترسی ورود ساخته می‌شود. فایل `config.php` موجود بازنویسی نمی‌شود. تنظیمات تولیدشده‌ی Nginx، FPM، systemd و logrotate نیز در اجرای دوباره بازنویسی نمی‌شوند.

برای امکان نگهداری سورس به‌صورت فقط خواندنی برای برنامه، در نخستین نصب، فهرست قدیمی `accounts.json` یک بار در `.panel/accounts.json` کپی می‌شود. فایل اصلی حذف یا تغییر نمی‌کند. از این پس **فهرست فعال حساب‌ها `.panel/accounts.json` است**. نشست‌ها، رسانه‌ها و وضعیت‌ها همچنان در همان `accounts/` می‌مانند. نصب دوباره فهرست فعال را از فایل قدیمی جایگزین نمی‌کند.

## ۳. تنظیم رمز و Telegram API

```bash
sudo nano /opt/self/config.php
```

تنها مقادیر موردنیاز را در فایل موجود تغییر دهید:

```php
'admin_password' => 'YOUR_LONG_UNIQUE_PASSWORD',
'api_id' => 123456,
'api_hash' => 'YOUR_32_CHARACTER_API_HASH',
'base_dir' => __DIR__,
'php_bin' => '/usr/bin/php8.3',
'timezone' => 'Asia/Tehran',
```

نمونه‌ی بالا مقادیر ساختگی دارد؛ فایل تنظیمات را با این قطعه جایگزین نکنید. رمز پیش‌فرض `CHANGE_THIS_PASSWORD` پذیرفته نمی‌شود. برای ساخت API ID و API Hash به [بخش API در تلگرام](https://my.telegram.org/apps) بروید. این‌ها توکن BotFather نیستند. از اطلاعات API و نشست‌ها مثل رمز حساب مراقبت کنید.

رمز پنل می‌تواند متن معمولی موجود یا خروجی `password_hash(..., PASSWORD_DEFAULT)` باشد. اگر رمز با `$` شروع می‌شود، برنامه آن را هش فرض می‌کند. برای رمز تازه بهتر است از رشته‌ای طولانی که با `$` شروع نمی‌شود یا هش استاندارد استفاده کنید. تنظیمات نمونه از متغیرهای `UBCC_ADMIN_PASSWORD`، `UBCC_API_ID` و `UBCC_API_HASH` نیز پشتیبانی می‌کند؛ در نصب پیش‌فرض FPM محیط پاک است، پس برای کاربر مبتدی ویرایش `config.php` روش توصیه‌شده است. متغیرهای `UBCC_PHP_BIN` و `UBCC_PROCESS_MODE` توسط سرویس‌ها تنظیم می‌شوند و بر مقادیر موجود فایل اولویت دارند.

```bash
sudo bash scripts/control.sh doctor
sudo systemctl enable --now userbot-supervisor
sudo bash scripts/control.sh status
```

`doctor` نسخه و افزونه‌ها، مسیر PHP CLI، تنظیمات ضروری، قابلیت اجرای پردازش و مجوز نوشتن داده‌ها را بررسی می‌کند؛ اطلاعات محرمانه را چاپ نمی‌کند. اگر نصب اولیه تنظیمات ناقص باشد، supervisor شروع نمی‌شود تا آن‌ها اصلاح شوند.

## ۴. بازکردن پنل با تونل امن

پنل پیش‌فرض فقط روی `127.0.0.1:8080` سرور گوش می‌دهد. در PowerShell کامپیوتر خود پنجره‌ی جدید باز کنید و آن را باز نگه دارید:

```powershell
ssh -N -L 8080:127.0.0.1:8080 USER@SERVER_IP
```

در مرورگر کامپیوتر، آدرس `http://127.0.0.1:8080` را باز کنید. ترافیک از تونل رمزگذاری‌شده‌ی SSH عبور می‌کند. پورت 8080 را در فایروال عمومی باز نکنید. اگر پورت کامپیوتر اشغال است، از `-L 8081:127.0.0.1:8080` و آدرس محلی پورت 8081 استفاده کنید.

### اختیاری: دامنه و HTTPS عمومی

ابتدا رکورد DNS دامنه را به VPS متصل کنید. در فایل `/etc/nginx/sites-available/ubcc`، مقدار `server_name` را دامنه بگذارید و `listen 127.0.0.1:8080;` را به `listen 80;` تغییر دهید. سپس:

```bash
sudo nginx -t
sudo systemctl reload nginx
sudo apt-get install -y certbot python3-certbot-nginx
sudo certbot --nginx -d panel.example.com --redirect
sudo certbot renew --dry-run
```

`panel.example.com` را جایگزین کنید؛ پورت‌های 80 و 443 باید در فایروال VPS و ارائه‌دهنده باز باشند. بعد از موفقیت گواهی، با `https://panel.example.com` وارد شوید. قالب Nginx تنها `/`، `/index.php`، `/api.php` و دو فایل مشخص CSS/JS را ارائه می‌کند. بلوک عمومی اجرای همه‌ی فایل‌های PHP یا `try_files` برای ریشه اضافه نکنید؛ این کار مرز حفاظت نشست‌ها و تنظیمات را از بین می‌برد.

## ۵. فعال‌سازی حساب

۱. با رمز پنل وارد شوید و «افزودن اکانت» را بزنید. نام دلخواه و یک کلید یکتا مثل `acc_1` وارد کنید. کلید باید حروف لاتین، عدد، `_` یا `-` داشته باشد و حداکثر ۶۴ کاراکتر است.

۲. QR Login را بزنید. در تلگرام موبایل به Settings → Devices → Link Desktop Device بروید و QR را اسکن کنید. QR ممکن است به‌صورت خودکار تازه شود. پنجره را تا نمایش ورود موفق باز نگه دارید.

۳. اگر رمز دو مرحله‌ای دارید، **رمز حساب تلگرام** را در همان پنجره وارد کنید؛ این با رمز پنل متفاوت است. فایل انتقال رمز با مجوز خصوصی و به‌صورت اتمی ساخته می‌شود و کارگر آن را پس از خواندن حذف می‌کند. زمان ورود رمز پنج دقیقه و زمان دریافت QR ده دقیقه است.

۴. بعد از ورود موفق، Start را بزنید و چند ثانیه صبر کنید تا وضعیت روشن شود. برای مشاهده چت‌ها و ارسال پیام، حساب باید روشن باشد. کارگر و QR هم‌زمان یک نشست را در اختیار نمی‌گیرند.

اگر حساب در فهرست قدیمی است ولی پوشه نشست همراه سورس منتقل نشده، باید ورود QR انجام دهید. صرف وجود رکورد حساب به معنی فعال بودن نشست نیست.

## ۶. استفاده روزانه و قابلیت‌ها

- داشبورد وضعیت، زمان اجرا و تعداد کمپین‌ها را نشان می‌دهد. Start درخواست اجرا را ثبت می‌کند؛ supervisor ظرف چند ثانیه آن را انجام می‌دهد. Stop قصد اجرا را نیز پاک می‌کند تا حساب پس از ریبوت خودکار روشن نشود. Restart نشست را نگه می‌دارد.
- در بازیابی حذف یا ویرایش، مقصد Saved Messages یا کانال قابل دسترسی حساب را انتخاب کنید. فیلتر شخصی، گروه و کانال و آستانه بازیابی تاریخچه از همان پنل تنظیم می‌شود. این قابلیت فقط داده‌ای را بازیابی می‌کند که ربات پیش‌تر دریافت و ذخیره کرده باشد.
- در ساعت پروفایل، روشن و خاموش‌کردن از پنل انجام می‌شود. خاموش‌کردن درخواست بازگردانی نام را ثبت می‌کند و ربات روشن در چرخه بعدی آن را اعمال می‌کند؛ منطقه زمانی از تنظیمات خوانده می‌شود.
- کمپین‌ها حداکثر ۲۰ مقصد username عمومی و حداقل فاصله ۱۰ دقیقه دارند. می‌توان آن‌ها را متوقف، فعال یا حذف کرد. محدودیت FLOOD_WAIT تلگرام باید رعایت شود؛ ارسال دوباره در زمان مجاز انجام می‌شود.
- مرور چت‌ها از IPC کارگر روشن استفاده می‌کند. فهرست به‌صورت محدود و کش‌شده خوانده می‌شود. تاریخچه پیش‌فرض ۵۰ پیام است؛ دانلود رسانه در هر درخواست محدود است و نمایش همه‌ی فایل‌های قدیمی تضمین نمی‌شود.
- آرشیو فقط پیام‌های حذف‌شده و موارد ثبت‌شده‌ی مربوط را نشان می‌دهد. حذف یک مورد، پاک‌کردن آرشیو و گزینه حذف کامل حساب، داده را واقعاً حذف می‌کنند؛ قبل از استفاده پشتیبان بگیرید. حذف حساب بدون گزینه پاک‌سازی، پوشه نشست را نگه می‌دارد.
- دستورهای تلگرامی `/help`، `/auto`، `/delete`، `/edit`، `/clock` و `/send_personal` در Saved Messages همچنان در کد موجودند. راهنمای دستورها را با `/help` بخوانید.

تنظیمات قابلیت‌ها از فایل JSON مشترک خوانده می‌شوند و معمولاً نیاز به ری‌استارت ندارند. در تداخل هم‌زمان، ادغام تغییرات ربات، تغییر جدید پنل را حفظ می‌کند. متنی که مقصد کمپین حین یک چرخه ارسال تغییر می‌کند ممکن است از چرخه بعدی اعمال شود.

## ۷. شروع، توقف، ری‌استارت و لاگ

در پوشه پروژه:

```bash
sudo bash scripts/control.sh status
sudo bash scripts/control.sh start
sudo bash scripts/control.sh stop
sudo bash scripts/control.sh restart
sudo bash scripts/control.sh accounts
sudo bash scripts/control.sh logs
```

این فرمان‌ها PHP-FPM و supervisor اختصاصی پروژه را مدیریت می‌کنند. توقف FPM ممکن است سایت‌های دیگری را هم که از همان سرویس FPM استفاده می‌کنند موقتاً متوقف کند؛ روی VPS مشترک این موضوع را در نظر بگیرید. Nginx در حالت Stop همچنان اجرا می‌شود و برای پنل پاسخ 502 می‌دهد. حساب‌هایی که قبلاً با Start فعال شده‌اند، پس از شروع مجدد سرویس یا ریبوت از فایل `enabled` بازیابی می‌شوند. خاموش‌کردن یک حساب در پنل مستقل از توقف موقت کل سرویس است.

فرمان مدیریت یک حساب:

```bash
sudo -u ubcc env UBCC_PROCESS_MODE=supervisor UBCC_PHP_BIN=/usr/bin/php8.3 /usr/bin/php8.3 console.php stop acc_1
sudo -u ubcc env UBCC_PROCESS_MODE=supervisor UBCC_PHP_BIN=/usr/bin/php8.3 /usr/bin/php8.3 console.php start acc_1
sudo -u ubcc env UBCC_PROCESS_MODE=supervisor UBCC_PHP_BIN=/usr/bin/php8.3 /usr/bin/php8.3 console.php restart acc_1
```

لاگ‌های خصوصی حساب در `accounts/acc_1/bot.log` و `qr_worker.log`، خطاهای وب در `.panel/php-error.log` و خطاهای supervisor در journal هستند. logrotate روزانه یا هنگام اجرای بعدی زمان‌بندی و عبور از ۱۰ مگابایت، با هفت نسخه چرخش انجام می‌دهد. `copytruncate` ممکن است تعداد کمی از خطوط هم‌زمان را از دست بدهد. لاگ‌ها داده خصوصی دارند؛ کل لاگ یا فایل نشست را در گروه عمومی منتشر نکنید. مقادیر تنظیمات محرمانه در خروجی برنامه پالایش می‌شوند و trace ورود QR در پنل نمایش داده نمی‌شود.

## ۸. پشتیبان، به‌روزرسانی و بازگشت

### پشتیبان سازگار

```bash
sudo bash scripts/backup.sh
```

این فرمان موقتاً FPM و supervisor را متوقف می‌کند تا نشست‌ها در حین کپی تغییر نکنند، فایل خصوصی `.panel/backups/ubcc-TIMESTAMP-PID.tar.gz` می‌سازد و سرویس‌های قبلاً روشن را دوباره شروع می‌کند. سورس، تنظیمات، فهرست فعال و حساب‌ها در پشتیبان هستند؛ vendor، پشتیبان‌های قبلی و نشست‌های موقت وب کنار گذاشته می‌شوند. **این فایل خروجی پشتیبان جدید است و ورودی نصب پروژه نیست.** آن را به محل امن دیگری خارج VPS کپی کنید؛ پرشدن دیسک یا از دست رفتن VPS، پشتیبان محلی را نیز از بین می‌برد. پشتیبان‌های قدیمی خودکار حذف نمی‌شوند.

### به‌روزرسانی فقط سورس

فایل‌های نسخه جدید را در یک مسیر موقت جدا روی VPS، مثلاً `/tmp/self-update` آماده کنید. سپس:

```bash
cd /opt/self
sudo bash scripts/update.sh /tmp/self-update
```

اسکریپت ابتدا نسخه جدید را آزمایش و پشتیبان تهیه می‌کند، سرویس‌ها را متوقف می‌کند و فقط فهرست مشخص سورس، assets، tests، scripts، deploy و docs را کپی می‌کند. `config.php`، `accounts/`، فهرست اصلی حساب‌ها و `.panel/` کپی یا حذف نمی‌شوند. Composer از lock جدید نصب می‌کند و آزمون، ممیزی و پیش‌بررسی انجام می‌شود. حساب‌های دارای قصد اجرا بعد از شروع سرویس برمی‌گردند. نسخه جدید باید مجموعه کامل فایل‌های همین ساختار را داشته باشد.

در شکست نصب یا آزمون پس از توقف، سرویس‌ها خاموش می‌مانند تا نسخه ناقص اجرا نشود. تغییر قالب‌های سرور به‌صورت خودکار روی تنظیمات فعال اعمال نمی‌شود؛ اختلاف فایل‌های `deploy/*.in` را با تنظیمات `/etc` بررسی کنید.

### بازیابی پس از به‌روزرسانی ناموفق

اسکریپت `scripts/restore.sh` ابتدا وضعیت فعلی را خصوصی پشتیبان می‌گیرد، سپس سورس، تنظیمات و داده‌ها را به پشتیبان انتخاب‌شده بازمی‌گرداند. راهنمای کامل و آثار بازگردانی در [راهنمای عملیات](docs/OPERATIONS_FA.md) آمده است. مسیر دقیق خروجی backup را جایگزین کنید:

```bash
sudo bash scripts/restore.sh /opt/self/.panel/backups/ubcc-TIMESTAMP-PID.tar.gz
sudo bash scripts/validate-vps.sh
```

بازگرداندن داده قدیمی، تغییرات پس از تاریخ پشتیبان را در نسخه فعال جایگزین می‌کند؛ پشتیبان قبل از restore نگه داشته می‌شود. نشست‌ها را دستی حذف نکنید.

## ۹. عیب‌یابی

| نشانه | بررسی و اقدام |
|---|---|
| پنل باز نمی‌شود | تونل SSH باید باز باشد؛ `sudo nginx -t` و `sudo bash scripts/control.sh status` را اجرا کنید. |
| خطای 502 | PHP-FPM یا socket اختصاصی اجرا نیست؛ `journalctl -u php8.3-fpm -n 50` را بررسی کنید. |
| QR ساخته نمی‌شود | `doctor`، فعال‌بودن supervisor، API ID/Hash و دسترسی شبکه VPS به تلگرام را بررسی کنید؛ لاگ خصوصی QR را بخوانید. |
| QR دیر ظاهر می‌شود | چند ثانیه برای صف اجرا صبر کنید؛ اتمام ورود قبلی یا خطای اتصال ممکن است کارگر را مشغول نگه داشته باشد. |
| وضعیت خاموش پس از Start | `sudo tail -n 50 accounts/acc_1/bot.log`؛ تلاش مجدد supervisor حداقل ۳۰ ثانیه فاصله دارد. |
| توقف کامل نمی‌شود | از کشتن PID تصادفی یا پاک‌کردن نشست خودداری کنید؛ پردازش ممکن است در ذخیره نشست باشد. لاگ را بررسی و توقف سرویس را انجام دهید. |
| حساب قدیمی از قبل اجراست | پیش از مهاجرت VPS، نسخه قبلی را از پنل قدیمی خاموش کنید. PIDهای قدیمی که به worker جدید تعلق ندارند، عمداً کشته نمی‌شوند. |
| `Permission denied` | مالکیت runtime باید `ubcc:ubcc` باشد؛ نصب VPS را دوباره اجرا کنید. سورس برای ubcc فقط خواندنی است. |
| JSON خراب | برنامه خطا می‌دهد و فایل را با داده خالی جایگزین نمی‌کند؛ سرویس را متوقف کنید، از فایل خراب کپی بگیرید و نسخه معتبر پشتیبان را بازیابی کنید. |
| پیام ارسال نمی‌شود | دسترسی مقصد، username، محدودیت‌های حساب و FLOOD_WAIT را بررسی کنید؛ ارسال زودتر از محدودیت را تکرار نکنید. |
| «تلاش زیاد» هنگام ورود | یک دقیقه صبر کنید؛ حذف کوکی محدودیت را دور نمی‌زند. |
| دیسک پر شده | `df -h` و `sudo du -sh accounts .panel/backups` را بررسی کنید؛ حذف رسانه یا پشتیبان را تنها بعد از نگهداری نسخه امن انجام دهید. |

تغییر رمز پنل نشست‌های وب موجود را فوراً باطل نمی‌کند؛ برای خروج اضطراری از همه، سرویس FPM را متوقف و فایل‌های نشست وب داخل `.panel/sessions/` را پس از اطمینان از مسیر پاک کنید. این پوشه با `accounts/*/session.madeline` متفاوت است؛ نشست تلگرام را پاک نکنید.

## ۱۰. نگهداری و آزمون

```bash
cd /opt/self
bash scripts/test.sh
composer audit --locked --no-dev
sudo logrotate -d /etc/logrotate.d/ubcc
sudo bash scripts/control.sh doctor
```

آزمون‌ها با تنظیمات و حساب ساختگی در مسیر موقت اجرا می‌شوند و حساب واقعی را دست‌کاری نمی‌کنند. آزمون lifecycle در Linux قفل نشست، PID، شروع و توقف و supervisor را با ربات ساختگی می‌آزماید؛ به تلگرام وصل نمی‌شود. اتصال و ورود واقعی را پس از نصب در پنل آزمایش کنید. بررسی موفق syntax و آزمون محلی به معنی تأیید اجرا روی هر VPS نیست.

اجرای `bash run.sh` صرفاً برای توسعه محلی است؛ [مستند PHP](https://www.php.net/commandline.webserver) سرور داخلی را مناسب تولید نمی‌داند. نیازمندی PHP ۶۴ بیتی از وابستگی موجود و [سورس رسمی MadelineProto](https://github.com/danog/MadelineProto/blob/v8/composer.json) مشخص است.

ساختار و نتیجه ممیزی در `AUDIT_FA.md` آمده است. پوشه `graphify-out/` نقشه اختیاری روابط سورس است و وابستگی اجرایی پروژه نیست.
