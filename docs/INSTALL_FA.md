# نصب و اعتبارسنجی روی Ubuntu 24.04 LTS

این راهنما برای همین پروژه است. کد PHP و پنل فارسی حفظ شده‌اند. هدف نصب، Ubuntu 24.04 با PHP 8.3 و معماری ۶۴ بیت است. آزمون Windows به معنی تأیید Nginx، FPM یا systemd نیست؛ وضعیت واقعی آزمون‌ها در `FINAL_AUDIT_FA.md` ثبت شده است.

## ۱. اتصال و انتقال پوشه

در مثال‌ها مسیر پروژه `/opt/self` است. اگر پروژه روی سرور از قبل در مسیر مجاز دیگری قرار دارد همان مسیر را جایگزین کنید. حساب SSH باید sudo داشته باشد. `USER` و `SERVER_IP` را با نام کاربر و IP خود عوض کنید.

روی **کامپیوتر شخصی، PowerShell**:

```powershell
ssh USER@SERVER_IP
```

روی **VPS، کاربر دارای sudo**:

```bash
sudo apt-get update
sudo apt-get install -y openssh-server ca-certificates
mkdir -p ~/self-upload
exit
```

برای انتقال نسخه تمیز، روی **کامپیوتر شخصی**:

```powershell
scp -r F:\project\self\releases\ubcc-20261011-ignore-audit\* USER@SERVER_IP:~/self-upload/
ssh USER@SERVER_IP
```

این پوشه نسخه قابل توزیع است و اطلاعات واقعی حساب ندارد. برای مهاجرت نصب قدیمی، خود پوشه موجود پروژه همراه `config.php`، `accounts.json`، کل پوشه `accounts/` و در صورت وجود `.panel/` را از مسیر امن انتقال دهید؛ نشست‌ها را از انتقال حذف نکنید. انتقال را در زمان توقف نصب قبلی انجام دهید. فایل‌های خصوصی را در پوشه وب عمومی نگذارید. سورس فعلی از قبل استخراج شده؛ نیازی به پیدا کردن آرشیو نیست.

روی **VPS، کاربر sudo، فقط نصب تازه**:

```bash
sudo test ! -e /opt/self && sudo mv ~/self-upload /opt/self
cd /opt/self
```

اگر `/opt/self` موجود است، این مرحله را اجرا نکنید و از روش update در راهنمای عملیات استفاده کنید.

## ۲. پیکربندی پیش از نصب

```bash
cd /opt/self
sudo test -f config.php || sudo cp config.example.php config.php
sudo nano config.php
```

در فایل موجود فقط مقدار گزینه‌ها را تغییر دهید؛ کل فایل را با نمونه زیر جایگزین نکنید:

```php
'base_dir' => __DIR__,
'admin_password' => 'YOUR_LONG_UNIQUE_PASSWORD',
'api_id' => 123456,
'api_hash' => 'YOUR_32_CHARACTER_API_HASH',
'php_bin' => '/usr/bin/php8.3',
'process_mode' => 'supervisor',
'timezone' => 'Asia/Tehran',
```

اطلاعات نمونه ساختگی است. API ID و API Hash را در [صفحه رسمی Telegram API](https://my.telegram.org/apps) بسازید؛ توکن BotFather کاربرد ندارد. رمز مدیر پنل با رمز دو مرحله‌ای تلگرام متفاوت است. رمز پنل باید بلند و یکتا باشد؛ رمز متنی که با `$` شروع می‌شود انتخاب نکنید چون کد آن را هش فرض می‌کند. نشست‌ها و این فایل را در پیام، مخزن عمومی یا گزارش منتشر نکنید.

اگر از Windows مهاجرت می‌کنید، `base_dir` قدیمی را به `__DIR__` تغییر دهید. PHP CLI و حالت supervisor از محیط سرویس نیز تنظیم می‌شوند. FPM محیط را پاک می‌کند؛ برای مبتدی ویرایش فایل تنظیمات روش مستقیم‌تر است.

## ۳. اجرای نصب

روی **VPS، کاربر sudo**:

```bash
cd /opt/self
sudo bash scripts/install-vps.sh
sudo bash scripts/control.sh doctor
sudo systemctl enable --now userbot-supervisor
sudo bash scripts/control.sh status
```

نصب بسته‌ها و وابستگی‌های قفل‌شده را دریافت می‌کند؛ Composer plugins و scripts اجرا نمی‌شوند. حساب بدون ورود `ubcc`، pool اختصاصی FPM، سایت Nginx روی loopback و سرویس ناظر ساخته می‌شود. کد برای `ubcc` فقط خواندنی و داده‌های اجرا خصوصی و قابل نوشتن است. نسخه پیش‌فرض دیگر PHP سیستم بر نسخه این سرویس اثر ندارد.

خروجی مورد انتظار doctor: «بررسی اولیه موفق بود». خروجی status باید `active (running)` نشان دهد. آزمون lifecycle روی Linux با حساب ساختگی اجرا می‌شود و ممکن است حدود یک دقیقه طول بکشد؛ به Telegram متصل نمی‌شود. اگر رمز/API ناقص باشد نصب ناظر را فعال نمی‌کند؛ پس از اصلاح، فرمان‌های بالا را اجرا کنید.

نصب مجدد فایل `config.php` و تنظیمات `/etc` موجود را بازنویسی نمی‌کند. پیش از تغییرات از نصب شناسایی‌شده پشتیبان می‌گیرد و سرویس‌ها را متوقف می‌کند. فهرست قدیمی تنها یک بار به `.panel/accounts.json` منتقل می‌شود؛ همه فیلدها و فایل قدیمی حفظ می‌شوند. نشانگر `.panel/storage.initialized` مانع بازگرداندن خودکار فهرست قدیمی بعد از گم‌شدن فهرست فعال است. نشست‌ها در `accounts/` باقی می‌مانند.

این اسکریپت سرویس PHP 8.3 FPM را متوقف/راه‌اندازی می‌کند؛ روی VPS مشترک، دیگر سایت‌های همان FPM نیز موقتاً تحت تأثیر قرار می‌گیرند. هدف پیشنهادی VPS اختصاصی است. تنظیمات قدیمی `/etc` عمداً حفظ می‌شوند؛ هنگام ارتقا قالب‌ها را با فایل نصب‌شده مقایسه کنید. `ExecStart` و `UBCC_PHP_BIN` باید `/usr/bin/php8.3` باشند.

## ۴. بازکردن امن پنل

در پنجره جدید **PowerShell شخصی**، تونل را باز نگه دارید:

```powershell
ssh -N -L 8080:127.0.0.1:8080 USER@SERVER_IP
```

مرورگر شخصی: `http://127.0.0.1:8080`. با رمز پنل وارد شوید. پورت 8080 سرور را عمومی نکنید. اگر پورت کامپیوتر اشغال است `-L 8081:127.0.0.1:8080` و آدرس محلی `http://127.0.0.1:8081` را استفاده کنید. تا قبل از HTTPS عمومی، همین تونل توصیه می‌شود. روش اختیاری دامنه/HTTPS در `README_FA.md` آمده است؛ دسترسی عمومی فقط پس از صدور گواهی و اجبار HTTPS مجاز است.

## ۵. اعتبارسنجی واقعی سرور

روی **VPS، کاربر sudo**:

```bash
cd /opt/self
sudo bash scripts/validate-vps.sh
```

این فرمان Composer، پیکربندی Nginx/FPM، واحد systemd، مجوزها، doctor، آزمون‌های ساختگی PHP/HTTP و مسیرهای واقعی Nginx را بررسی می‌کند. برای `/config.php`، `/.panel/accounts.json`، مسیر نشست، vendor و log انتظار HTTP 404 دارد. API بدون ورود باید 401 بدهد. logrotate در حالت debug بررسی می‌شود و فایل واقعی چرخانده نمی‌شود. متن موفق انتهای اسکریپت فقط مربوط به همین آزمون‌ها است.

برای ثبت خروجی بدون چاپ اطلاعات حساب:

```bash
sudo bash scripts/validate-vps.sh > ~/ubcc-validation.txt 2>&1
echo $?
```

کد خروج صفر یعنی این اجرا موفق بوده است. خروجی را پیش از اشتراک‌گذاری بررسی کنید. آزمون سرور، reboot و Telegram در این workspace اجرا نشده‌اند؛ باید روی VPS شما تکمیل شوند.

## ۶. اولین حساب و استفاده

۱. «افزودن اکانت» را بزنید؛ نام و کلید لاتین یکتا مانند `acc_1` وارد کنید. ۲. QR Login را بزنید و از تلگرام موبایل، Settings → Devices → Link Desktop Device اسکن کنید. ۳. در صورت درخواست، رمز دو مرحله‌ای همان حساب را وارد کنید؛ برای QR ده دقیقه و برای رمز پنج دقیقه فرصت است. ۴. پس از پیام ورود موفق Start را بزنید؛ وضعیت باید روشن شود. ۵. در Saved Messages دستور `/help` بفرستید و پاسخ را بررسی کنید. سپس چک‌لیست کامل راهنمای عملیات را اجرا کنید.

کلید حساب بدون فاصله، شامل حروف لاتین/عدد/`_`/`-` و حداکثر ۶۴ کاراکتر است. وجود رکورد قدیمی، به‌تنهایی نشانه داشتن نشست معتبر نیست. Start در حالت supervisor درخواست اجرا را ثبت می‌کند؛ برای اثبات اجرا چند ثانیه بعد وضعیت را بخوانید.

## ۷. خطاهای متداول

| خطا | اقدام |
|---|---|
| API یا رمز مدیر ناقص | `sudo nano config.php` سپس `sudo bash scripts/control.sh doctor` |
| base_dir نامعتبر | آن را به `__DIR__` در همین پروژه تغییر دهید |
| 502 از پنل | `sudo systemctl status php8.3-fpm` و `sudo php-fpm8.3 -t`؛ سپس log FPM |
| 403 یا فایل asset ناخوانا | `namei -l /opt/self/assets/app.js`؛ پوشه‌های والد باید قابل عبور باشند، برای داده‌ها chmod 777 ندهید |
| فهرست فعال موجود نیست/JSON خراب | سرویس را متوقف و نسخه معتبر `.panel/accounts.json` را از پشتیبان بازیابی کنید؛ نشانگر را حذف نکنید |
| Composer شبکه یا audit ناموفق | اتصال/DNS/ساعت سرور را اصلاح کنید؛ audit یا lock را دور نزنید |
| سرویس متعلق به مسیر دیگری است | نصب قبلی را بررسی کنید؛ یک مجموعه سرویس با نام ثابت تنها برای یک پروژه است |
| worker روشن نمی‌شود | doctor، اعتبار QR و لاگ حساب را بررسی کنید؛ برنامه را با root یا اجرای موازی `bot.php` راه نیندازید |
| QR منقضی یا 2FA ناموفق | QR تازه بسازید، ساعت سیستم و رمز حساب را بررسی کنید؛ فایل نشست را دستی حذف نکنید |

برای لاگ، restart، backup، restore و update فرمان‌های کامل در `OPERATIONS_FA.md` است.
